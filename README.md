# 黒猫亭 ― 迷宮のほとりの酒場

Wizardry 風の迷宮に複数の冒険者パーティが潜る様子を、酒場の店主として「遠見の水晶」で眺める放置RPG。

- 単一の HTML ファイル（`index.html`）で動く。ブラウザで開くだけで遊べる
- 進行はブラウザの localStorage に保存され、閉じているあいだも時間が進む

## 舞台

ハルヴァント大陸の東、灰の荒野。約80年前に沈んだエスタリアの王都の跡に開いた全30階の迷宮と、そのほとりの街ロウエン。
若い店主が借金をして開いたばかりの黒猫亭が、三十年来の老舗・銀の杯亭を追いかける。

詳しい設定は [docs/setting.md](docs/setting.md)。

## 主な仕組み

- 冒険者：種族・職業・出身・年齢・性別・性格・口調・口癖・得意不得意・夢・二つ名・絆
- 一行：リーダーが仲間を集めて結成（基本6人）。後継ぎ・解散・仲間割れあり
- 迷宮：30階・7区画・転移の石碑・名のある魔物・黒竜・沈んだ王、記録の断片
- 鉄の山脈の坑道：迷宮を踏破すると開く二つ目のダンジョン。坑道B1〜25F・4区画・坑道王
- 店：借金の返済、席の拡張、回復薬の差し入れなどの支援、武具屋・地図屋、番付
- 持ち込まれる話：借金を返し終えると、店に話が持ち込まれる。誰を主役に回すかを、話の文面の手がかりと冒険者の個性を照らし合わせて決める。見込んだ常連を3人まで選べる

ゲームの仕組みの詳しい決まりは [docs/spec.md](docs/spec.md)。

## 仕様のテスト

`docs/spec.md` に書かれた決まりが成り立っているかを確かめる。node だけで動き、ブラウザは要らない。

```
node tools/spec-test.mjs                 # 完全版。乱数の種を48個、それぞれ30000刻（600日）回す。4コアで3分ほど
node tools/spec-test.mjs --quick         # 速い版。完全版と同じ並びの先頭12種だけを回す。4コアで50秒ほど。PR の自動テストはこちら
node tools/spec-test.mjs --seeds 40 --ticks 10000
node tools/spec-test.mjs --seed 8919     # 不合格のとき、反例に出た種だけを回して再現する
node tools/spec-test.mjs --jobs 2        # 同時に回す数を絞る。環境変数 SPEC_TEST_JOBS でも指定できる（ふだんは CPU のコア数）
node tools/spec-test.mjs --shard 2/4     # 種を4つに分けたうちの2つめだけを回す。種に関係ない確かめは 1/4 だけで行う
```

- 仕様の表（席の拡張、店の設備、借金の返済など）とコードの値が一致するかを見る。
- ゲームを回しながら、毎刻成り立つはずの性質（席の数を超えない、伝説の品は世界にひとつずつ、など）を見る。
- 種ごとに別のスレッドで回す。進捗の行と合否は種の順に出すので、同時に回す数を変えても、出力と合格・不合格は同じになる。ゲームの中身がエラーで止まった種も不合格になる。
- 速い版の12種は毎回同じで、完全版の先頭（1000 から始まり、7919 ずつ足す）である。種を減らすと、めったに起きない不具合は見逃しやすくなる。引数なしは完全版のまま。
- 不合格なら、最初の反例（種・刻・中身）を出して、終了コード1で終わる。
- 古いセーブの見本（`tools/old-saves/vNN.json.gz`）を一つずつ今の migrate にかけ、今の版になること、冒険者・一行・記念碑などの数と店の金が変わらないこと、今のコードで店を開いたときにいつもある項目がそろうこと、そのまま30日回せることを見る。見本は、版ごとにその版で最後のコミットのコードで店を300日回して保存したもの（`node tools/old-saves/make.mjs` で作る。同じコミットからは同じ見本ができる）。リポジトリの履歴が版24から始まるので、見本は版24から。
- セーブの版（SAVE_V）を上げる PR では、上げる前の版の見本が `tools/old-saves/` になければ、`make.mjs` の表にその版と、上げる前の main のコミットを足して作る。
- 自動テストでは、pull request のときは速い版、main への push と毎晩（日本時間 0:00）と手動実行のときは完全版を回す。どちらも種を4つに分けて（`--shard`）4つのジョブで並べて回し、画面のテストも別のジョブで同時に回す。4つの分を合わせると、分けないときと同じ種と同じ確かめになる。

## 釣り合いを測る

迷宮と坑道が何日目に、どちらの店の、どのくらいのレベルの一行に踏破されるかを、乱数の種ごとに測る。**大きな変更をしたら、支援なしと支援ありの両方で測り、結果を PR に書く。**

```
node tools/measure.mjs                          # 種8個、1200日まで。支援なしと支援ありの両方
node tools/measure.mjs --seeds 16 --days 1400   # 釣り合いを決めるときはこちら（4コアで2分あまり）
node tools/measure.mjs --seeds 16 --days 1400 --base origin/main   # 変更前（origin/main）も同じ種で測り、変更後と並べる
node tools/measure.mjs --mode support           # 片方だけ（none か support）
node tools/measure.mjs --detail                 # 50日ごとの坑道の最深と上位のレベルも出す
node tools/measure.mjs --fresh                  # 残してある結果を使わずに、すべて測り直す
```

- **支援なし**：店主は何もしない。借金は毎月の返済だけで返す。
- **支援あり**：店主が毎日1度、手元に蓄えを残しながら、帳場と武具屋の支援を使う。借金を早めに返す。借金が残っているあいだは、次の返済額に2000Gの余裕を足した分を残し、返済日まで22日を切ったら蘇生・地図・薬の店負担を止める（新人への支度の品は渡す）。借金を返し終えたあとは、席を広げ、回復薬10本・地図代・蘇生代・新人への支度の品の方針をすべて使い、常連に品を贈り、設備を下の段から建て増し、寺院に寄進し、親方に特注を打たせる。引き抜き・裏通りの酒場・持ち込まれる話・見込みは使わない。
- 種ごとに、借金の完済日、迷宮の踏破日と店と一行のレベル、坑道が開いた日、坑道の底に着いた日、坑道王と戦った回数、坑道の踏破日と店と坑道王と戦う前の一行のレベルを出す。
- 最後に、どちらの店が何回踏破したか、踏破日の中央値、借金完済の中央値、評判の中央値をまとめる。支援ありでは、店の設備の段ごとに、建てた日の中央値も出す。
- 看板の後継ぎが継いだか継がなかったかを、跡継ぎの性格ごとに数えた表も出す（黒猫亭と銀の杯亭の合計）。
- いちばん最後に、PR に貼れる表を出す。行は支援なしと支援ありで、`--base` のときは変更前と変更後が並ぶ。表には、初回の返済で罰金を取られた種の数も入れる。
- **結果を残す**：結果は種ごとに `.cache/measure/` に残す（git には入れない）。エンジン（`index.html` の ENGINE の部分）、`tools/measure.mjs` と `tools/engine.mjs`、種、日数、Node の版がどれも同じなら、測り直さずに残した結果を使う。`--base` で測った変更前も残るので、変更を直して測り直すときは、変更後の分だけを回す。何本を測り、何本を残した結果で済ませたかは、最後に出す。
- **`--base`**：git のコミットやブランチを渡す。手元の `main` は古いことがあるので、`git fetch origin main` をしてから `origin/main` を渡す。見出しに、実際に使ったコミットが出る。変更前のエンジンも、今の `tools/measure.mjs`（支援ありの店主も今のもの）で回す。
- 測るときは水晶のログを残さない。文字化けの乱数は同じ回数だけ引くので、結果はログを残したときと変わらない。
- 全滅の回数（店と、迷宮か坑道か）と、階を問わない死因（変異の肩書きは外す）も数える。表には出さず、下の指紋で使う。

## 釣り合いの指紋

measure と同じ中身を、決まった16種・1400日で支援なしと支援ありの両方について回し、種ごとの結果を `tools/fingerprint.json` に残しておく。シミュレーションの結果が変わると指紋も変わるので、釣り合いを変えたことに気づかずに main に入るのを防ぐ。

```
node tools/fingerprint.mjs --check    # 回して tools/fingerprint.json と比べる。違えば、どの種の何が変わったかを出して終了コード1（4コアで2〜3分）
node tools/fingerprint.mjs --update   # 回して tools/fingerprint.json を書き直す
node tools/fingerprint.mjs --shard 3/8 --out part.json   # 32本を8つに分けた3つめだけを回して結果を書く（CI で使う）
node tools/fingerprint.mjs --check --from DIR            # 回さずに、DIR にある --out の結果を合わせて比べる
```

- 種ごとに残すもの：借金の完済日、初回の返済、返済の罰金の回数、迷宮の踏破日と店とレベル、坑道が開いた日、底に着くまでの日数、坑道王と戦った回数、坑道の踏破日と店と戦う前のレベル、全滅の回数（店ごとに迷宮と坑道）、倒れた人数、多い死因の上位3つ、最後の評判、黒猫亭の売上。1種を1行に書くので、差分で変わった種が分かる。
- **シミュレーションの結果が変わる変更では、`--update` で書き直して同じ変更に入れる。** 釣り合いに効く変更なら、上の measure で変更前と並べて測り、PR に書く。結果を変えないつもりの変更（表示だけの直しなど）で指紋が変わったら、どこかが乱数の引き方か結果を動かしている。
- `tools/measure.mjs`（支援ありの店主を含む）を変えても指紋は変わることがある。そのときも書き直す。
- **死因の偏り**：measure の帯（坑道B8〜15F、迷宮B11〜15F、迷宮B16〜22F）と全体について、16種を合わせて、魔物に倒された人数のうち、いちばん多い魔物が占める割合を指紋に残し、55%（`tools/fingerprint.mjs` の `SKEW`）を超えたら不合格にする。宝箱のわなは魔物とは別の死因なので、分子にも分母にも入れない（種ごとの死因の記録には残す）。魔物に倒された人数が100人に満たない帯は見ない。
- 自動テストでは、32本を8つのジョブ（`--shard`）に分けて並べて回し、まとめのジョブで `--check --from` で比べる。指紋が違ったとき、または pull request で指紋を書き直したときは、続けて `node tools/measure.mjs --seeds 16 --days 1400 --base 基のブランチ` を別のジョブで回し、PR に貼れる表をジョブの要約（Summary）に、全文を成果物（measure）に残す。このジョブは時間がかかるので、まとめの test は待たない。指紋を書き直した PR は、指紋が合っていれば合格になる。
- 自動テストは Node 22 で回す。Node の版で結果が変わらないとは確かめていないので、`--update` も Node 22 で回す。

## 画面のテスト

ゲームの中身ではなく、画面まわりの決まり（タブが裏から戻ったときの「留守のあいだに」など）を、本物のブラウザで `index.html` を開いて確かめる。Playwright の Chromium を使う。

```
npm install && npx playwright install chromium   # 最初の一度だけ
node --test tools/browser-test.mjs               # 2分ほど
```

- 時計は偽物に差し替えて、開いたときの時刻で止めておき、テストが進めたぶんだけ進める。乱数（`Math.random`）は種を決めて固定する。どちらも、結果がページを開いてからの実時間や、たまたまの乱数で変わらないようにするため。タブの表と裏は、ページの見え方を差し替えて起こす。

## lint

`index.html` の `<script>` を取り出して ESLint にかけ、使っていない名前（no-unused-vars）と、宣言していない名前（no-undef）を見つける。

```
npm install            # 最初の一度だけ
node tools/lint.mjs    # 見つかれば index.html の行番号つきで出し、終了コード1で終わる
```

- 関数の引数は見ない（同じ形で並べた表の関数が、使わない引数を持つため）。
- テストや measure からだけ使うトップレベルの名前は、`index.html` の `/*ENGINE START*/` のすぐ下にある `/* exported … */` に並べる。
- 自動テストでも別のジョブで回す。
